# Content Security Policy (CSP) Runbook

## Overview
This runbook describes the Content Security Policy configuration for the Janata Bank Late Sitting, Holiday & Night Duty Banking Portal.

## Current Architecture
The application sets security headers at the reverse proxy/edge layer in `src/proxy.ts`.

### 1. Enforced Header (`Content-Security-Policy`)
To maintain zero regressions for client-side document generation, dynamic charts, and legacy styling while remaining backward compatible, the following policy is enforced:
```http
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval' blob:; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com https://fonts.maateen.me https:; style-src-elem 'self' 'unsafe-inline' https://fonts.googleapis.com https://fonts.maateen.me https:; img-src 'self' data: blob: https:; font-src 'self' data: https://fonts.gstatic.com https://fonts.maateen.me https:; connect-src 'self' https: ws: wss:; frame-ancestors 'self'; object-src 'none'; base-uri 'self';
```

### 2. Candidate Strict Header (`Content-Security-Policy-Report-Only`)
Because Chunk 3 self-hosted all webfonts (`Noto Sans Bengali` and `Inter`) into `src/fonts/` without external font CDN dependencies, a tighter strict CSP is tested in report-only mode:
```http
Content-Security-Policy-Report-Only: default-src 'self'; script-src 'self' 'unsafe-inline' blob:; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self'; frame-ancestors 'self'; object-src 'none'; base-uri 'self';
```

## Transport Security (HSTS) Note
The `Strict-Transport-Security` header:
```http
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
```
**Important**: HSTS is evaluated and cached by modern browsers only when served over valid HTTPS connections. If served over plain HTTP, browsers safely ignore this header. In production, ensure Nginx terminates TLS (port 443) with the provided SSL configuration template in `nginx.conf`.

## Verification Steps
1. Make a request to the portal:
   ```bash
   curl -I http://localhost:3000/
   ```
2. Verify both headers are returned:
   - `Content-Security-Policy`
   - `Content-Security-Policy-Report-Only`
3. Inspect browser developer tools Console for any violation reports generated by `Content-Security-Policy-Report-Only`.
